# Project docs

Lightweight requirements, design, and decision records, kept alongside the
code so they version with it. Established as a series convention in
Module 1, chapter 2.

- `prd/` — mini-PRDs: user stories and acceptance criteria, one per module
- `design/` — ER diagrams, API contracts, and flow diagrams, one per module
- `adr/` — Architecture Decision Records: short, dated notes on judgment
  calls and why they were made

From Module 2 onward, new PRD/design docs are introduced at the start of
each module's first video rather than in a standalone episode.
